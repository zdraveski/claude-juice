# Release A (juice 1.4.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make juice safe for strangers: still by default, ask before reading the login token, and say where to look when it breaks.

**Architecture:** A new `motion` setting drives two things: whether the real line animates, and which refresh time juice writes into Claude Code's `settings.json`. `fable: 'auto'` now needs an existing Fable reading, and the `/juice` skill asks before setup. The status line's error path adds a dim hint. Main protection already exists (ruleset `main`), so the release only checks it.

**Tech Stack:** Node 24+ ES modules, `node:test`, no dependencies. The customizer is plain browser JS in `web/`.

**Spec:** `docs/superpowers/specs/2026-11-15-release-a-design.md`

## Global Constraints

- **Motion values:** `motion` is `'on'` or `'off'`, default `'off'`.
- **Refresh values juice writes:** `[1, 30, 60]`. Motion on means 1, motion off means 60.
- **Hand-picked refresh:** any other value of 1 or more was chosen by hand and is never changed.
- **Known limit:** a 1 chosen by hand can't be told apart from juice's own 1, so it moves to 60. The changelog tells people how to get it back.
- **Writes to `settings.json`:**
  - read with `readClaudeSettings`, which aborts on a broken file
  - write with `writeSettings`, which is atomic and keeps a symlink a symlink
  - only when the command runs this config folder's launcher (`isJuice(sl) && runsLauncher(p, sl.command, platform)`)
- **Never throw:** these additions must never make a status line run throw. Anything new that can fail sits in its own `try/catch`.
- **Cost wording:** "about a sixth of a CPU core per open window".
- **Token question:** it covers these points, wording free:
  - juice reads your Claude login token from this computer
  - it sends it only to Anthropic, about every 5 minutes, and never stores it
  - you get the Fable battery and up-to-date numbers in windows you're not using
  - saying no keeps Session, Weekly and Memory working
  - Mac only: macOS will ask once for Keychain access
- **User-facing words:** plain and short, in the README's voice.
- **Tests:** `node:test` with `node:assert/strict`, in a throwaway `mkdtemp` `CLAUDE_CONFIG_DIR`, never the real `~/.claude`. Run them with `node --test`.
- **Git:**
  - work on branch `feat/release-a`
  - stage explicit paths, never `git add -A`
  - end each commit with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`

## Review Focus

1. **Crowded `settings.json`:** a file holding permissions, hooks, env and theme. The one-time move or `set motion` must bring every other key back exactly as it was. Tested in Task 2.
2. **Broken or half-written `settings.json`** when the move runs, for example while the person is editing it. The line must still draw, and the file's bytes must stay unchanged. Tested in Task 2.
3. **Damaged `juice-cache/fable.json`** on Windows or Linux with `fable: auto`. The battery stays on, because the file exists, and juice fetches again; nothing crashes. Tested in Task 3.
4. **Empty or partial stdin** on Claude Code's first draw. No error hint shows unless juice really failed. Tested in Task 4.
5. **Several windows doing the once-per-update move together.** They all end at the same file; a second `matchRefresh` changes nothing. Tested in Task 2.

- Produces, in `src/launcher-file.js`: `upgradeLauncher(p, pluginRoot) -> boolean`. It is `true` when this run did the once-per-update check, whether or not it replaced the launcher, and `false` on the fast path. Nothing reads the old return value.
